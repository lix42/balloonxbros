# Balloon x Bros

Pre-order site for a kid-run twist-balloon school fundraiser for Kirkland
Middle School (KIMS). Spec and design tokens: `docs/DESIGN.md`. Placeholders
still to fill: `docs/PLACEHOLDERS.md`. Ask the owner (Li) rather than guessing
real-world facts (prices, dates, menu, school info).

## Stack

- React 19 + TanStack Start (SSR on Workers) + Vite + TypeScript in `src/`.
  File routes in `src/routes/`; `src/routeTree.gen.ts` is generated by the
  Start plugin on dev/build and committed (`pnpm run check` runs before build
  in CI).
  Start's default server entry is the Worker (`wrangler.jsonc` `main`).
  Server-only code uses `env`/`waitUntil` from `cloudflare:workers`; never
  touch `window`/`localStorage` during render.
- Styling: Tailwind v4 (Vite plugin) with shadcn on Base UI. Theme in
  `src/styles/app.css`: the `docs/DESIGN.md` tokens as colours (neutrals
  `ground`, `ink`, …; stepped hues `accent-500`, `red-500`, `yellow-200`,
  `blue-300`, …; text and links `ink-2`, headings `blue-300`, focus ring green
  `accent`), Fredoka/Montserrat, radii, and
  shadcn's semantic variables mapped onto them. No hex in page code except
  artwork. Site variants of shadcn parts live in
  `src/components/ui/` (`buttonVariants`: red/ink/pill/link/icon/tab;
  `Input` 48px/44px; `Checkbox`). Add components with
  `pnpm dlx shadcn@<version> add <name>`, then restyle to the tokens. Base
  UI's `Button` defaults to `type="button"`: pass `type="submit"` in forms.
  No dark mode.
- Node 24 for all tooling (dev, build, tests' host, wrangler, CI), pinned in
  `.nvmrc`; `engines` + `engineStrict` (pnpm-workspace.yaml) make pnpm refuse
  other versions. The Worker itself runs on workerd, not Node.
- API: the logic is plain functions in `worker/service.ts` (env + input in,
  data out, or a thrown `HttpError` with a status and a message safe to show).
  `src/server-fns.ts` wraps each one as a Start server function returning a
  `Result` (`{ ok, data }` or `{ ok: false, status, error }`), which
  `src/api.ts` unwraps into an `ApiError`. File downloads are server routes:
  `/api/files/photos/…` and `/api/admin/orders/$id/receipt`. Admin functions
  take an `AdminAuth`, which only `requireAdmin` (cookie check) creates. Tests
  call `worker/service.ts` directly (the test pool gets a stub `main`,
  `tests/worker.ts`, since Start's entry needs its Vite plugin to build).
- D1 (`DB`) for items, orders, settings — schema in `migrations/`.
- R2 (`FILES`) for receipt uploads (`receipts/`) and item photos (`photos/`).
- Menu content lands by migration (`0004_menu.sql` replaced the `0001` seed
  items) or /admin; see `docs/PLACEHOLDERS.md`. Every item has a stock count
  (`stock` NULL = unlimited survives only on legacy rows); `items.category` is
  unused (always `'menu'`).
- Resend for the customer confirmation email and a "New order" note to
  `contact_email` (reply-to the buyer); both skipped when `RESEND_API_KEY` is unset.
- Domain: balloonxbros.com (registered on Cloudflare).
- Vite+ (`vite-plus`, the `vp` CLI) wraps Vite, Vitest, Oxlint and Oxfmt;
  config lives in `vite.config.ts` (`fmt`, `lint` blocks). `vite`/`vitest` are
  pinned through the `catalog` and `overrides` in `pnpm-workspace.yaml`
  (`vite` is Vite+'s core build); bump them with `vite-plus`. Generated files
  and the tasks-CLI docs are excluded from formatting there.
- pnpm, version pinned in `packageManager` (Corepack or a plain `pnpm` picks it
  up). Dependency install scripts are off except those in `allowBuilds`.
  pnpm 12's `minimumReleaseAge` policy rejects lockfile entries published
  less than a day ago. It failed CI's frozen install even though the local
  install passed. Pick the newest version older than a day rather than
  relaxing the policy.

## Commands

- `pnpm run dev` — Vite+ dev server + local Worker/D1/R2 (run
  `pnpm run db:migrate:local` first)
- `pnpm run check` — the CI gate: `vp check` (Oxfmt format check, type-aware
  Oxlint and type check), `tsc -b`, then tests. Keep `tsc -b`: `vp check`
  type-checks a file under only one tsconfig, so `shared/` (in the app, worker
  and tests projects) is never checked without the DOM lib, though the Worker
  bundles it. `pnpm run typecheck` is `tsc -b` alone.
  Tests run inside workerd via `@cloudflare/vitest-plugin` with local D1
  (migrations applied) and R2; `tests/api/` drives the Worker through its
  real entry point.
- `pnpm run fix` — format and apply lint autofixes (`vp check --fix`).
- `pnpm run build` / `pnpm run deploy`

## Conventions

- Money is integer cents everywhere; format only in the UI.
- Stock decrements happen in one D1 batch; `items.stock` has a
  `CHECK (stock IS NULL OR stock >= 0)` so an oversell aborts the batch.
- Admin auth: `ADMIN_PASSWORD` secret → HMAC-signed cookie (`SESSION_SECRET`),
  `Path=/` so server functions (`/_serverFn/…`) receive it.
- Mobile first; touch targets ≥ 44px; no emoji icons.
